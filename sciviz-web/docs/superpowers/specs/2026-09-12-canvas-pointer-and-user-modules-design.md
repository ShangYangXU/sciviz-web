# 画布指针合一 + 常用工具栏 + 自建模块（设计）

- 日期：2026-09-12
- 状态：已实现
- 影响范围：`sciviz-web/`

## 1. 问题

三件事各自独立，但都指向同一个诉求：**画布上的动作应当由"手放在哪儿"决定，而不是先让用户去挑一个工具。**

1. **工具是多余的中间状态。** 现在画布左上角有「箭头 / 抓手」两个按钮，另有 `V` / `H` 快捷键。用户要做的事情其实只有一件：拖空白 = 移动画布，拖模块 = 移动模块。多出来的工具有三个代价：每次切换是一次额外判断；切到抓手后节点整体 `pointer-events: none`，"我现在还能不能选中节点"要靠记忆；`H` 在输入框外还会劫持按键。
2. **常用节点要滚动查找。** 节点库是分组的，一个工作流反复用到的往往只有那三五个模块。每次都要展开分组、在列表里找一遍。
3. **模块只能用内置的。** 现有 `custom.script` 让用户写函数，但它是匿名的一次性副本：没有名字、没有分类、不能复用、关了页面就没了。同一段预处理要在三个工作流里各抄一遍。

## 2. 目标与非目标

**目标**

- G1 取消工具切换：指针悬停在**空白**上是手（拖动平移画布），悬停在**模块**上是箭头（可选中、可拖动、可接线）。
- G2 多选不能因此丢掉：按住 `Shift` 拖空白仍是框选。
- G3 画布上有一条**常用工具栏**，把常用的模块钉进去，点一下就落到视口中央。
- G4 可以**定义模块**：名字 + 分类 + 说明 + Python 代码，保存后进节点库、可钉进常用栏、可编辑、可删除、跨会话保留。
- G5 自建模块是**真执行**的：和 `custom.script` 走同一条引擎路径，形参即输入端口、`return` 的 key 即输出端口，报错给完整 traceback。

**非目标（本切片不做）**

- N1 把多个节点折叠成一个子图模块（复合模块）。自建模块现在是"一个函数"，不是"一段子图"，判据是先把"单函数模块"用起来。
- N2 工程容器（`Project`）的持久化。架构总纲 §3 里 `Project` 仍然缺失；本切片只把**工作台配置**（自建模块清单、常用栏）落在浏览器本地，工程内容仍不落盘。
- N3 模块的导入导出与分享（YAML 里现在只会出现 `type`，不带模块定义本身）。

## 3. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| D1 | 指针行为由**悬停对象**决定，用 React Flow 自带的 `panOnDrag` + `selectionKeyCode` 实现，不自己写鼠标状态机 | 平移、框选、节点拖拽都要和缩放/触摸/自动平移协同，自己写一份必然在边界上漏。React Flow 的语义正好是"空白拖动即平移，按住框选键拖动即框选" |
| D2 | 框选改走 `Shift`（`selectionKeyCode`），并在节点库提示里写明 | 空白上的左键被平拿走之后，多选必须有替代入口；`Shift` 是这套框架的默认值，也是同类工具的通行做法 |
| D3 | 自建模块 = **一个命名的 Python 函数**，端口一律由签名解析 | 与 `custom.script` 同一套机制，代码是唯一真相，不引入第二处端口声明；避免"声明了端口但代码里没有"这种必然对不上的状态 |
| D4 | 自建模块的 `type` 以 `custom.user.` 开头，**创建时定下、编辑时不变** | 两个约束同时满足：`custom.*` 前缀让它落进引擎已有的用户函数路径；稳定的 type 让画布上已有的节点和 YAML 不会因为改了个名字就全部失效 |
| D5 | 自建模块与常用栏落在 `localStorage`，读写全部包在 `try/catch` 里 | 纯本地前提（C1）下没有别的存法；隐私模式/存储被禁用时读写会抛异常，功能应当降级为"本次会话有效"而不是白屏 |
| D6 | 常用栏放在**画布左上角**，节点库里的每个条目带一枚星标 | 常用栏的价值是"不用找"，放在节点库里就还得先看左边栏；星标留在库里，因为"钉哪一个"是在浏览时决定的 |

## 4. 交互

```
指针在空白 ── 按下左键拖动 ──▶ 平移画布（光标：hand → grabbing）
指针在空白 ── Shift + 拖动 ──▶ 框选（光标：crosshair）
指针在模块 ── 拖动 ─────────▶ 移动模块（光标：箭头）
指针在端口 ── 拖动 ─────────▶ 拉线（光标：crosshair）
滚轮 / 触摸板双指 ──────────▶ 平移（沿用）
空格按住 + 拖动 ────────────▶ 临时平移（沿用）
```

常用工具栏（画布左上角）从左到右依次是：**已钉住的模块** → `＋ 模块`（打开"定义模块"）。

- 星标不在常用栏里时：点一下钉住；已在常用栏里时：点一下取消。
- 常用栏里的每一项点一下就把该模块加到视口中央（落点复用节点库的"找空槽位"逻辑）。

## 5. 数据结构

自建模块就是一个 `NodeTypeDef`（`src/workflow/types.ts`），与内置节点同构 —— 这是它不需要在别处再声明一遍的原因：

```ts
{
  type: 'custom.user.filter_3f2a',   // 创建时定下，编辑不变
  label: '带通滤波',
  category: 'feature',
  description: '按截止频率做带通滤波',
  inputs: [],                        // 空：端口由代码签名解析（与 custom.script 同一条路径）
  outputs: [],
  params: [{ key: 'code', label: '函数代码', type: 'code', default: 'def ...' }],
  assetRecipes: [{ kind: 'dataset', nameTemplate: '<label>' }],
  mockDurationMs: 500,
}
```

本地存储（键 `sciviz.workbench.v1`）：

```json
{ "modules": [ /* NodeTypeDef[] */ ], "favorites": ["custom.user.filter_3f2a", "viz.density"] }
```

`favorites` 里可以同时有内置与自建模块的 type。读取时**过滤掉已经不存在的 type**，否则删掉一个自建模块后常用栏会留一个点不动的空按钮。

## 7. 验收标准

- A1 画布上不再有工具按钮，`.canvas-host` 上不再有 `tool-select` / `tool-pan` 类。
- A2 空白处拖动平移画布；`Shift + 拖动` 能框选到 ≥2 个节点；拖动模块能移动模块。
- A3 悬停空白时光标是 `grab`、悬停模块时是箭头（`default`）。
- A4 在节点库里点星标 → 该模块出现在常用栏；点常用栏条目 → 画布上多出该节点；再点星标 → 从常用栏消失。
- A5 定义一个新模块（含 Python 代码）→ 它出现在节点库与常用栏；刷新页面后仍在。
- A6 自建模块接线后由引擎**真算**：探针能看到它的真实输出；代码写错时节点上给出 traceback。
- A7 删除自建模块后，常用栏里对应的项一并消失。

## 8. 风险

| 风险 | 处理 |
|---|---|
| 用户失去"拖空白框选"的习惯 | 节点库与空白画布提示里明确写 `Shift`；框选矩形本身仍是原来那个 |
| `localStorage` 被禁用（隐私模式） | 读写包 `try/catch`，功能降级为本次会话有效，界面提示"这次改动不会保留" |
| 自建模块的代码在别人的机器上跑不出来 | 与 `custom.script` 同样的定位：本地代码、本地执行；节点上仍带"⚠ 代码"徽标 |
| 用户以为自建模块是"复合子图" | 定义弹窗里写明"自建模块是一个 Python 函数：形参即输入端口，return 的 key 即输出端口" |

## 9. 实现记录（与设计的偏差）

| # | 项 | 结果 |
|---|---|---|
| I1 | 自建模块的执行 | 按设计的 D3 落地：`custom.user.*` 加进 `isEngineNode` / `needsUserFn`，与 `custom.script` 同一条 userfn 路径，端口由签名解析。**没有**变成模拟节点 |
| I2 | 常用栏的位置 | 除画布左上角那条之外，节点库每个条目也带星标（D6 原本只写了"画布左上角放常用栏"，实际两处都有：钉的时候在库里，用的时候在画布上） |
| I3 | 自建模块的资产 | `assetRecipes` 给的是 `{ kind: 'dataset' }`，所以返回表的模块会以模块名进资产库；返回指标 / 图的模块暂时不进资产库（等各自的迭代） |
| I4 | e2e 用例 | 新增三条：单一指针（光标 + 平移不误选）、常用栏（钉住 → 加节点 → 移除）、自建模块（定义 → 节点库/常用栏 → 接线后引擎真跑出数）。原先的两条"工具切换"用例已按新交互改写 |
| I5 | e2e 辅助函数 | 顺带修了三处拖拽脆弱点：按**端口**（而不是整个节点框）构图、松手前重量一次落点、端口被别的节点压住时先把挡路的挪开。第三处在画布拥挤时必现 —— 宽节点（数据预览 380px）与列间距（260px）不匹配会压住邻居的输出端口，是布局的已知问题，不在本切片范围内 |
