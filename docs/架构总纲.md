## 0. 一句话

**契约是第一性对象，其余一切都是它的客户端。**

本项目要解决的问题是"把模型训练、评估与数据分析的数据流变成显式契约"，因此架构的中心不是画布、不是引擎、也不是 AI，而是**一份可以被校验、被序列化、被复算的图（IR）**。画布是它的一个视图，YAML 是它的一个序列化，agent 是它的一个操作者，CLI 是它的一个无界面入口。

判断某个设计是否合格，只问一句：**它是在强化契约，还是在绕过契约？**

## 1. 目标与硬约束

**目标（按优先级）**

| 编号 | 目标 | 可验证的判据 |
|---|---|---|
| G1 | 可复现 | 同一工程 + 同一数据，第二次运行得到一致结果；不可复现项被显式列出 |
| G2 | 可校验 | 大部分契约违约在**运行前**被拦住，并给出稳定错误码 |
| G3 | 可被 agent 操作 | agent 不读源码即可读懂、修改、运行、自检一张图 |
| G4 | 可复用 | 图能被他人接手；节点边界标准化，内部实现自由 |
| G5 | 本地优先 | 数据不出本机；浏览器可直接运行 |

**硬约束**

- C1 核心功能纯本地、无必需服务端依赖。可选远程模型是显式外发适配器，不得成为校验、执行、保存或复现的前提；默认不外发行值、权重与图片像素（见[对话栏设计](./对话栏设计.md) §3.2 / §9）。
- C2 浏览器可运行：重型计算必须能在 Web Worker 中执行。
- C3 不引入需要服务端的运行时依赖。
- C4 现有交互体验（实时重算、逐节点探针）不得退化。

## 2. 分层架构

**2026-10-02 公开前整理基线。** 当前目录沿用 `src/` 分层，不为目录好看一次性迁移到 packages。
自建模块通过纯注册表的 `registerCustomModuleProvider` 注入即时快照，注册表不再反向依赖 Zustand；
浏览器资产包装移至 `src/store/runAssets.ts`，原 `workflow/executor.ts` 不再承担执行或资产职责。
`check:layers` 遍历 L0/L1/L3/计划器的运行时依赖，阻止直接或间接导入 store、DOM、React、Worker、Pyodide 或 Node IO。
已实现和未实现的当前状态以[公开前审查](./公开前审查.md)及可运行检查为准；下文早期“现状”保留设计背景。

依赖方向**只能向下**。下层不得知道上层的存在。

```
L5  Clients        画布 UI ｜ YAML 编辑器 ｜ Agent 工具面 ｜ CLI(headless) ｜ 界面对话栏 ｜ 报告导出
                         ↓ 只通过 Facade 调用
L4  Facade         用例层：validate / run / patch / inspect / export / migrate
                         ↓
L3  Runtime        执行面：调度器、Job 生命周期、缓存、运行清单、取消/恢复
                         ↓ 通过适配器接口
L2  Adapters       pyodide-worker（现在）｜ local-process（未来真训练）｜ simulated（模拟）
                         ↓
L1  Contract       类型系统、校验规则、错误码、指纹算法
                         ↓
L0  Core IR        图、节点、边、端口描述符、算子清单、身份、序列化
```

**依赖规则（可机检）**

- R-A UI 不得 import 任何 Adapter。现状违反：`src/canvas/ProbePanel.tsx` 直接 `import { head } from '../engine/client'`。应改为经 Facade 或经产物缓存读取。
- R-B Core IR 与 Contract 层必须是**纯逻辑**：不依赖 DOM、不依赖 Worker、不依赖 React、不依赖 Pyodide。现状 `src/engine/plan.ts` 已经做到（可直接被 `node --test` 跑），这是要推广到全部 L0/L1 的样板。
- R-C 唯一的执行入口是 Runtime；UI 不做任何求值决策。

## 3. 核心 IR（唯一事实来源）

IR 是"这个工程长什么样"的唯一权威表示。其他任何形式（React Flow 的节点数组、YAML 文本、UI 的 selection 状态）都是它的**派生视图**，不得反向成为真相来源。

| 对象 | 职责 | 现状对应 |
|---|---|---|
| `Project` | 工程容器：图 + 数据引用 + 环境锁 + 运行记录 | **缺失**（当前零持久化） |
| `Graph` | 节点 + 边 | `Workflow`（`src/workflow/types.ts`） |
| `NodeTypeManifest` | 算子清单：id、version、implementationHash、IO 契约、参数 schema、执行等级、确定性等级 | `NodeTypeDef`（`src/workflow/nodeRegistry.ts`） |
| `PortDescriptor` | 端口类型描述符 | `PortSpec` + `PortType`（需升级，见契约规格 §4） |
| `Value` / `Artifact` | 带身份与血缘的值 | `nodeOutputStore` 的 `refs`（需补身份） |
| `Fingerprint` | 求值键 | `nodeFingerprint`（`src/engine/plan.ts`） |
| `Job` | 一次求值 | **缺失**（当前散落在 `graphRunner.tick`） |
| `RunManifest` | 一次运行的可复现记录 | `Run`（`src/workflow/types.ts`，仅记录状态与耗时） |

**复合组块也是 IR 节点。** `WorkflowNode.group` 内联保存一张子 `Workflow`、明确的边界输入/输出映射和对外参数映射；它不通过本机模块库里的名称间接引用定义。画布导航路径只是视图状态，不进入工程图。创建组块时保留内部节点与内部连线，外部连线改接组块边界，内部参数经稳定 key 暴露在组块上。

节点卡片默认只呈现必接输入、已有连线的参数端口与输出；带默认值的参数在右侧栏编辑，需要接线时由右侧栏临时展开该端口。端口仍全部由清单和函数签名解析，卡片显隐不改变契约。用户为参数写的简短说明保存在节点的 `paramNotes` 中，仅供界面解释变量，不参与求值指纹；英文参数名仍是机器接口的稳定 key。

画布批注仍保存在工程顶层 `annotations:` 中，不进入 `Workflow` 或执行图；每条批注用 `groupPath` 记录所属画布层级。缺少该字段的旧批注属于主画布。打开组块只显示 `groupPath` 与当前导航路径完全一致的批注，组块复制、封装、解散和删除须同步维护这些归属。

**关键决定：算子清单（Manifest）是节点能力的唯一声明处。**
一个节点属于哪个执行等级、由哪个适配器实现、是否需要 seed、是否有 `any` 端口，全部写在 Manifest 里。**不允许存在第二处清单。**

> 现状（2026-09-13 起已合规）：每个算子在 `NodeTypeDef` 里用四个**必填**字段自报家门 —— `runtimeClass`（归谁算）、`version` 与 `implementationHash`（哪一版实现）、`determinism`（可复现到什么程度）、`execClass`（执行等级）。`ENGINE_NODES` 白名单已删除，新增算子只改一处，漏写编译不过。
>
> 仍欠的是**Job 模型本身**（下方 P1）：`execClass` 现在只是声明 + 记录，调度还没有按它分流，长任务的进度与取消也还没有。

### 4.4 复合组块的执行

组块不新增执行适配器。统一纯逻辑展开函数将根图里的组块递归展开为现有普通节点：组输入映射为内部入边，组输出映射为内部出边，对外参数覆盖对应内部节点参数；内部节点 ID 以组实例 ID 命名空间化。随后计划器、GUI Runtime 与 CLI 共用展开后的图。组定义及其映射必须进入展开结果与指纹，避免内部逻辑改变后命中旧缓存。禁止循环定义和超过实现所设最大递归深度的图。

## 4. 执行面（Runtime）

### 4.1 统一 Job 模型

**一切求值都是 Job。** 实时小算子与几小时的训练不是两种东西，只是执行等级不同（契约规格 §6.1）。

```
Job = {
  key: Fingerprint          // 唯一标识"算什么"
  nodeId, execClass         // interactive | background | batch
  inputs: 上游产物引用
  determinism: deterministic | seeded | stochastic
  status, progress, logs, artifacts, error
}
```

这条统一的直接收益：当训练从"模拟"变成"真跑"时，**调度器、缓存、探针、运行清单、agent 接口全都不需要改**，只换适配器。

> **2026-09-13：`progress` 与取消落地（T7，仅宿主侧）。** 宿主按 Job 上报进度、接受 `cancel`；
> 取消由算子在可中断点上生效（协作式 —— 同步 Python 里插不进中断），取消后的 Job 停在
> `cancelled`、清掉产物、但**保留指纹**（否则调度会立刻重跑它，表现为"取消没生效"）。
> 浏览器侧做不到取消（Pyodide 里是同步调用），界面因此不显示取消按钮。
> 仍欠：`execClass` 只是声明与记录，调度还没有按它分流。

### 4.2 调度（沿用现有机制，补齐边界）

现有 `src/engine/graphRunner.ts` 的机制是正确的雏形，予以保留：

订阅变更 → 防抖（300ms）→ `planEvaluation`（纯函数，算谁该重算）→ 求值 → 再 plan，直到无待算。

需要补的是：

1. **调度与执行分离**：`plan.ts` 决定"算什么"（纯函数、可单测），Adapter 决定"怎么算"。现状已基本如此，保持。
2. **缓存查询进调度**：求值前先查 `指纹 → 产物` 缓存，命中则跳过执行。
3. **Job 生命周期显式化**：现在是内联的 status 赋值，应收敛为 Job 状态机，使 batch 类的取消/恢复有着落。
4. **已知简化**：当前用 64 轮定点循环逐层推进。它正确但不必要——按拓扑序一次即可。列为 P1 待收，不阻塞。

### 4.3 缓存与产物

`ArtifactStore` 把本次运行产出的文件登记进 `RunManifest`；训练权重另按不可变制品身份保存。每次成功训练都分配新的 `artifact_id`，输入指纹只用于说明训练设置，不作为目录键或覆盖依据。

> 现状对应：`src/store/nodeOutputStore.ts`（版本号 + refs + head 缓存）是雏形。升级点有三：键从"节点 id + 版本号"改为**指纹**；产物必须带身份与血缘；**必须跨会话持久化**。

训练产物按 `.artifacts/<artifact_id>/` 保存 `model.pt`（仅 `state_dict`）与 `meta.json`。先在同一文件系统的临时目录写入、回读校验并计算摘要，再原子改名为最终目录并登记；失败时不产生可见制品。`.sciviz` 的 `modelArtifacts` 只保存工程对制品的引用（节点、`artifact_id`、训练输入指纹），不保存权重，也不进入节点参数或指纹。**打开工程后必须自动按引用恢复**：只有该工程已有且指纹完全相同的引用允许自动恢复，并在恢复成功后继续下游求值；不增加额外的“加载模型”步骤。缺失、校验失败或定义不兼容时阻断模型输出并提示重新定位或重新训练，绝不静默重训或改用别的制品。引用过期后节点停止自动执行；用户可显式重新训练并创建新的制品版本，旧版本保留。

制品引用与实际运行记录是两种现有元数据：工程引用随 `.sciviz` 往返，运行记录继续写入 `nodes[].artifacts`；不增加平行的制品索引。关闭宿主、关闭工程、参数变化和重新训练均不删除旧制品。清理候选必须在引用来源完整可查、无工程/固定/收藏引用且超过保留期限时才能产生；删除前需要展示引用情况并由用户确认，执行时移入可恢复的回收区。

当前不提供制品删除或自动清理入口，因此运行过程不会清除制品。后续增加清理功能前，必须先实现工程/固定/收藏引用的完整扫描与可恢复回收区。

**当前最严重的缺口：项目零持久化。** 全仓库没有任何 `localStorage` / `IndexedDB` / 文件读写，刷新页面即全部丢失。对一个以"可复现"为价值主张的工具，这是必须先补的一项——它同时是 G1 和"产物缓存"的地基。

## 5. 适配器层

适配器是唯一允许接触"外部世界"（Worker、Python、文件系统、网络）的地方。

```ts
interface RuntimeAdapter {
  id: string
  capabilities(): { execClasses: ExecClass[]; supportsCancel: boolean; supportsResume: boolean }
  run(job: Job, ctx: RunContext): Promise<ArtifactRefs>
  cancel(jobId: string): void
}
```

| 适配器 | 用途 | 现状 |
|---|---|---|
| `pyodide-worker` | 浏览器内真 Python（数据变换、特征、自定义脚本） | `src/engine/client.ts` + `engineWorker.ts` + `python/*.py` |
| `simulated` | 尚未实现真算法的算子，返回**显式标记**的模拟产物 | `src/workflow/executor.ts`（需重构为适配器，见下） |
| `local-process` | 本地宿主：GPU 训练、大内存、长任务 | `sciviz-local`（`run-host.ps1`；宿主专属算子见 `sciviz_host/gpu_ops.py`） |
| `remote` | 更远的将来 | 非目标 |

**算子属于哪个适配器，由它的依赖决定，不由人指定。** 判据是"浏览器能不能提供那个库"
（Pyodide 的包表，见 `sciviz-web/node_modules/pyodide/pyodide-lock.json`）：能，算子就是
共享的，两个适配器都能跑；不能，它只能是宿主专属，并在 Manifest 里声明。
2026-09-13 定：按"宽边界"走 —— 能用 scipy / scikit-learn 等浏览器真有的库，
只有 torch 这一类落进宿主专属。机检脚本 `sciviz-web/scripts/check-shared-operator-deps.mjs`。

> **"并在 Manifest 里声明"这件事已落地（2026-09-13）**：`NodeTypeDef.requires`
> 写明 `runtime: 'both' | 'host'`、需要的包与一句原因。于是：
> 界面在**跑之前**就能标出"这个要本地宿主"；核在浏览器引擎下会**当场拦下**它
> 并给出下一步（而不是让引擎回报一句"不认识的算子"）。
> 两条机检守着它：`check-shared-operator-deps.mjs`（边界之内的算子不许 import 边界之外的库）、
> `src/contract/hostOperators.test.ts`（`gpu_ops.OPERATORS` 与 `requires.runtime = host` 一一对应）。

**重构要点：把 `executor.ts` 从"平行实现"降级为"一个适配器"。**
现状：`executor.ts` 是 492 行的独立执行路径，自己拓扑排序、自己睡时间、自己造资产卡片，与真引擎并列。目标：它只保留"对某类 Job 返回模拟产物"的能力，并在产物上打 `simulated: true`。这样"模拟"从架构上的**第二条路**变成适配器的一种**能力**，`ENGINE_NODES` 白名单随之消失。

## 6. 数据层

- 导入管线（`src/data/*`：Worker 解析 → 列式存储）保持不变，这是已经做对的部分。
- 数据集身份升级为 `DatasetRef`（内容哈希 + schema + 采样率 + 单位），见契约规格 R3.2。
- **数据面板的列开关属于"视图"而非"数据"**，但必须并入指纹（现有实现已经正确处理，见 `plan.ts` 注释），否则开关列不会触发重算。
- 采样率与单位是数据属性，不是算子参数（R3.4）。
- 桌面本地模式可在启动时预载一份固定 CSV：本地宿主只开放该文件的专用读取接口，界面仍走现有 CSV Worker 和数据集身份流程；预载只把数据加入数据集列表，不改写已有工作流连线。路径通过 `SCIVIZ_FIXED_DATASET_PATH` 配置，未设置时不预载，固定读取接口返回未配置。

## 7. 客户端层

五个客户端，共享同一个 Facade：

| 客户端 | 职责 | 现状 |
|---|---|---|
| 画布 UI | 编辑图、查看参数与探针 | `src/canvas`、`src/components`、`src/charts` |
| YAML | 图的文本往返 | `src/workflow/yaml.ts` |
| Agent 工具面 | 机器操作 | **缺失** |
| CLI（headless） | 无界面校验与运行，供 CI 与 agent | **缺失** |
| 界面对话栏 | 在当前工程里对话、@ 块、提案/应用补丁、运行与取证；不新增契约语义 | **设计已定、未实现**（见[对话栏设计](./对话栏设计.md)） |

外部 MCP 的实时画布操作仍经过同一 Facade：`sciviz canvas` 通过本机宿主把白名单请求转给当前前台浏览器页；页面内调用现有 `inspectCanvasGraph` / `runGraphPatch` / `runGraphUndo` 与 Zustand store。宿主只负责认证、焦点页选择和请求转发，不接收 JavaScript、不读写 React 内部对象。CLI 原有基于已保存 `.sciviz` 的无头用法保持独立，避免把浏览器状态伪装成磁盘状态。

### 7.1 Agent 面（设计要点）

agent 是本项目的一等使用者，其接口按契约规格 P3 设计：

| 工具 | 作用 | 关键要求 |
|---|---|---|
| `get_ir_schema()` | 返回 IR 的 JSON Schema | **自描述**，agent 不需要读源码或猜格式 |
| `validate(patch)` | 静态校验，返回错误码 | 复用 L1 校验器，与 UI 同一实现 |
| `apply_patch(patch)` | 受限补丁：增删节点/边、改参数 | **不得**是任意代码执行；有界动作空间 |
| `run(scope)` / `status()` / `cancel()` | 执行 | 与 UI 走同一个 Runtime |
| `inspect(nodeId, portId)` | 取真实值 | 与探针同源 |
| `explain(errorCode, ctx)` | 解释与修复建议 | 错误码表即文档 |

**审计要求**：agent 的每一次修改都落为可 diff 的补丁并记录结果，使"agent 改了什么、为什么"可回看、可回滚。

**与"直接写 Python"的竞争关系**：agent 的默认替代方案是写脚本。脚本给不了的四件事——边界约束、增量重算、逐边验证、有界动作空间——就是本项目的立足点。这四条一旦失守，agent 没有理由使用本平台。

### 7.2 CLI（为什么必须有）

`sciviz validate ./project.sciviz` / `sciviz run` / `sciviz export`。

它不是锦上添花：无界面运行是**复现与 CI 的前提**，也是逼着执行面与 UI 彻底解耦的杠杆。只要 headless 跑得起来，分层就是真的。

## 8. 工程与持久化

工程文件 `.sciviz`（文本，可 diff、可入库、可被 agent 读写）：

```yaml
version: 1
graph:                       # IR：节点 + 边 + 端口描述符
datasets:                    # 数据引用（内容哈希为身份）
  - id: ds-1
    contentHash: sha256:...
    schema: { ... }
    sampleRate: 1000
environment:                 # 环境锁
  nodePacks:                 # 算子包版本（ComfyUI 失效点的解法）
    core: 1.4.0
runs: []                     # 运行清单
```

浏览器侧持久化：IndexedDB（图 + 数据缓存 + 运行记录）。文件侧：导出/导入同一份文本。

## 10. 演进路线

| 阶段 | 内容 | 完成判据 |
|---|---|---|
| **P0 契约落地** | `PortDescriptor` + `NodeTypeManifest` + L1 校验器 + 错误码表 + 算子版本进指纹 + 数据集内容哈希 + `fs` 移出算子参数 + `split` 泄漏检查 | 现有 23 个算子全部声明具体类型（消除内置 `any`）；构造一张泄漏图能被**静态**拦住；改一次算子实现能使下游全部失效重算；现有 17 个单测仍全绿 |
| **P1 执行面统一** | Job 模型 + `executor.ts` 降级为模拟适配器 + 缓存键改为指纹 + IndexedDB 持久化 | 刷新页面后图与产物仍在；同一图重跑命中缓存；模拟产物在清单中带 `simulated: true`；`ENGINE_NODES` 白名单被删除 |
| **P2 工程化** | `.sciviz` 工程文件 + 运行清单 + headless CLI | 能在无界面环境下 validate 一个工程并输出稳定错误码，可进 CI |
| **P3 Agent 面** | IR JSON Schema + 工具面 + 补丁审计日志 | agent 不读源码即可搭出"数据→分帧→特征→划分→训练→评估"一张图，并通过自检 |
| **P4 扩展与真训练** | 节点包契约 + 版本迁移流程 + 至少一个真训练适配器 | 训练产物带完整运行清单；第二次运行可复现到指定容差；不可复现项被显式列出 |

## 11. 明确的非目标

- 不做通用 BI / 数据大屏（不是 DataEase、openDataV 那一类）。
- 不做云端协作与托管（C1）。
- 不做一键 AutoML、不做模型 zoo。
- 不做数据标注。
- 不在 P0–P2 阶段追求大数据的性能指标（先把契约立住，性能是 P4 之后的事）。

## 12. 架构决策记录（ADR）

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| A1 | IR 是唯一事实来源，UI 只是客户端 | 否则 agent、CLI、YAML 各自维护一份真相，迟早不一致 | 需要一次结构调整 |
| A2 | 标准化在端口与连线，自由度在节点内部 | 唯一能同时满足"可定制"与"可复现"的切法 | 端口设计要走在前，短期比"先跑起来"慢 |
| A3 | 一切求值统一为 Job | 训练与实时算子共用一套调度/缓存/清单，换真训练时零改动 | 需要引入 Job 概念与状态机 |
| A4 | 模拟是适配器能力，不是平行路径 | 消除 `ENGINE_NODES` 两处真相；模拟产物必须显式标注 | 需重构 `executor.ts` |
| A5 | 算子带版本与实现哈希，且参与指纹 | 直接消除"改了代码、结果显示为最新"的静默错误 | 每次改算子都会使缓存失效（这是**期望行为**） |
| A6 | 错误码稳定且机器可读 | agent 与 CI 只能消费结构化错误 | 需要维护错误码表 |
| A7 | 本地优先、浏览器可运行 | 数据不出本机；零部署成本；这是相对桌面方案的主要差异 | 性能受浏览器限制，重训练必须外接适配器 |
| A8 | 不做一次性大重构 | 项目只有几天历史，稳定性优先；旧新路径并行期以单向收敛为准 | 过渡期存在两套代码，需要纪律 |
| A9 | 组块定义随图内联保存，运行前展开成普通图 | 文件离开本机后仍能执行；不再引入平行的子图调度和适配器 | 节点 IR 与序列化递归；运行时需命名空间化内部 ID |
