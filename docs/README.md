# 项目文档索引

本目录是项目的**唯一方案与设计来源**。改动定位或架构时，先改这里，再改代码。

第一次使用请先读 [使用引导手册](./使用引导手册.md)，按示例认识界面和日常操作。下面的方案与规范主要面向需要理解或修改项目的读者。

| 文档 | 性质 | 作用 |
|---|---|---|
| [使用引导手册.md](./使用引导手册.md) | 面向用户（2026-10-02） | 从第一张图到数据、画布、参数、图表、子空间、记录、训练与 Agent 协作的小功能指南 |
| [公开前审查.md](./公开前审查.md) | 当前实现审查（2026-10-02） | 结构、数据流、BYOK、隐私范围与验证结果 |
| [方案V3.md](./方案V3.md) | 定位与范围 | 项目是什么、为谁做、不做什么、路线图与风险 |
| [架构总纲.md](./架构总纲.md) | 设计基线 | 分层结构、核心 IR、执行面、适配器、目标目录、演进阶段、架构决策记录 |
| [数据契约规格.md](./数据契约规格.md) | **规范性** | 端口类型、兼容规则、求值键、错误码、当前差异清单。实现层面的判据 |
| [训练面设计.md](./训练面设计.md) | 设计基线 | 训练这一个面：一个循环（谁拥有什么）、五档接管（想改什么就改哪一档）、控制项与判据、明确不做的两条 |
| [Agent面设计.md](./Agent面设计.md) | 设计基线 | agent 的入口与抓手、动作空间、证据与汇报格式、双向对称性、验收与落地顺序 |
| [MCP面设计.md](./MCP面设计.md) | 设计基线（stdio 与实时画布已实现，仍在演进） | agent 工具面的第二种传输：MCP 有哪些工具、返回什么、怎么实现、明确不做什么；训练链路的实测边界与缺口 |
| [MCP性能分析与加速方案.md](./MCP性能分析与加速方案.md) | 实测分析与实施建议（2026-10-01） | 外部工具全链路、契约与协议缺陷、瓶颈原文对照与评分、保持完成质量的分阶段加速方案；不替代现行接口规格 |
| [对话栏设计.md](./对话栏设计.md) | v0.2 决策稿（**C0–C4 已落地**） | 界面内的 agent 入口：第五个客户端、上下文与提示词、@/粘贴块、会话状态机与审计、图/用户代码/源码三套闸门、并发基线、回放与 MCP 薄壳验收 |
| [接口文档.md](./接口文档.md) | **规范性**（只追加） | 接口登记册：CLI、wire 协议、HTTP 面、文件格式、模块 API，以及变更记录。改接口前先查、改完必记 |
| [待办.md](./待办.md) | 工作队列（会频繁变动） | 现在轮到哪一条：判断依据、完成判据、触碰面、并行冲突 |
| [开发日志.md](./开发日志.md) | 只追加 | **为什么**这么做（做了什么看 git log） |

阅读顺序：**方案V3 → 架构总纲 → 数据契约规格 →（要碰训练时）训练面设计 → Agent面设计 →（要做界面之外的工具面时）MCP面设计 →（要做界面内的对话栏时）对话栏设计 → 接口文档 → 待办**。

`sciviz-web/docs/` 下是具体功能切片的设计记录（如"万能数据探针"），属于实现细节，从属于本目录。
