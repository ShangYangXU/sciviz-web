## 0. 这份规格解决什么问题

模型训练、评估与数据分析的真实痛点不是"没有工具"，而是**流程里的数据流没有契约**：

1. 每一步的输入输出长什么样，只存在于写脚本那个人的脑子里和临时 print 里。
2. 同一个变换在两份脚本里行为不同（要不要去均值、在哪一步分帧、归一化统计量算在全量还是训练集）。
3. 换个人接手、或半年后自己重跑，结果对不上，且不知道对不上在哪一步。
4. 数据换了、代码改了，系统仍按旧结果继续往下走，且不报警。
5. 流程无法被机器读懂，因此无法被 agent 操作，也无法进 CI。

本规格把"每一步承诺什么、谁来保证、违约怎么报"写成可判定、可序列化、可校验的条文。**它不是文档装饰，是后续所有实现的判据。**

## 1. 三条第一原则

### P1 自由在节点内部，标准在端口和连线上

节点内部可以是任意实现——任意 Python、任意库、任意算法。但它的**输入输出端口必须符合本规格声明的类型**。

这条原则化解了产品上最大的一个伪矛盾：*"像 ComfyUI 那样可定制"* 与 *"数据流可复现"* 在同一根轴上是对立的（ComfyUI 正因既无类型约束、节点包又独立版本化，成为可复现性的反面教材）。立下 P1 之后二者不再冲突：**定制发生在边界之内，标准化发生在边界之上。**

推论：`custom.script` 这类"任意代码"节点是本规格的**必要组成部分**，不是例外——它内部任意，但端口照样受约束。

### P2 能在运行前判定的，不留到运行后

契约的价值主要来自静态可判性。连线时就能拦住的错误（类型、轴序、单位、数据泄漏、缺随机种子），必须在连线时拦住并给出可读原因。只有运行后才知道的（实际形状与声明漂移），才用抽样校验单独表达（§7）。

### P3 契约机器可读，错误机器可定位

图和错误的消费者不止是人，还有 agent 与 CI。因此：

- 图必须能序列化为**纯文本且往返无损**（YAML/JSON），这是 agent 唯一被允许的动作面。
- 任何契约违约必须报**稳定错误码** + 结构化上下文（`nodeId` / `portId` / 期望 / 实际），不允许只给人读的散文。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 算子 Operator | 一种可复用的变换，有唯一 id、版本与实现哈希 |
| 节点 Node | 算子在某个图里的一次实例化（带参数） |
| 端口 Port | 节点上具名的输入/输出位置，携带类型描述符 |
| 值 Value | 端口上流动的东西；必带身份与血缘（§3） |
| 产物 Artifact | 被物化并登记的值，可供下游与报告引用 |
| 求值 Job | 一次"算出某节点某端口的值"的执行单元（§6） |
| 运行 Run | 一次跨越多个节点的完整执行记录，是复现的最小单位 |
| 工程 Project | 图 + 数据引用 + 环境锁 + 运行记录的持久化容器 |

## 3. 值与身份

**R3.1** 任何流经端口的值都必须携带身份：`内容哈希 + 形状 + dtype + 血缘`。

**R3.1a（可观察摘要）** 对 `table` 输出，执行面可在 `nodeResult.refs[port]` 中返回不含原始行值的
`columns`、`rowCount`、`timeColumn` 与按列 `stats`（`count/min/max/mean/std`，非有限值写 `null`）；
所有输出 kind 均可带 `identity`（本次求值指纹）与 `lineage`（上游 `nodeId:portId` 列表）。这些字段
只用于发现、核对和追溯，不替代显式的 `head` 行值授权，也不把运行中的未物化张量伪装成 table。

**R3.2** 数据集身份 `DatasetRef` 至少包含：

```
contentHash   内容哈希（不是"行列数 + 列名"这类形状签名）
schema        列名 → dtype
rowCount      行数
timeColumn    时间列（可空）
sampleRate    采样率 fs（可空）
units         列 → 单位（可空）
```

> 现状差异：当前 `datasetSignature`（`src/engine/graphRunner.ts`）只算 `行数 | 时间列 | 启用列名`。两份列名列数相同、内容不同的 CSV 会被判定为同一份数据，从而复用错误的引擎侧状态。这是必须修的第一类缺陷。

**R3.3** 无法提供身份的产物（如某次随机初始化的权重）必须显式声明 `volatile: true`，并因此**禁止进入缓存**。

**R3.4 采样率与单位是数据的属性，不是算子的参数。**
`fs` 属于 `DatasetRef`；要改变采样率，必须经过显式的**重采样算子**，由它产出新的 `DatasetRef`（新 `sampleRate` + 新内容哈希）。

> 当前项目已移除内置频域特征节点。需要频域分析时，应在项目外或 `custom.script` 中显式完成，
> 并由用户负责把采样率作为数据契约的一部分传递；系统不再替工作流隐式猜测采样率。

> `viz.density.sampleRatio` 是概率密度估计的取点比例，范围为 `0~1`：`1` 使用全部输入点，
> `0` 表示不取点，中间值按比例等间隔取点。图表前端会按算子实际输出的点数读取数据。

## 4. 端口类型系统

### 4.1 描述符

端口类型不是枚举，而是描述符：

```ts
type PortKind = 'table' | 'tensor' | 'model' | 'metrics' | 'figure' | 'scaler' | 'any'

/** 轴语义，顺序即轴序 */
type AxisRole = 'sample' | 'channel' | 'time' | 'feature'

type DType = 'float32' | 'float64' | 'int64' | 'bool' | 'string'

type Split = 'none' | 'train' | 'val' | 'test'

type Determinism = 'deterministic' | 'seeded' | 'stochastic'

interface PortDescriptor {
  kind: PortKind
  /** tensor 必填；table 隐含 [sample, feature] */
  axes?: AxisRole[]
  dtype?: DType
  /** 物理量单位；无量纲写 '1' */
  unit?: string
  /** 划分归属 */
  split?: Split
  determinism?: Determinism
  /** 该端口是否用于"拟合/统计估计"——决定 R4 泄漏检查是否生效 */
  fits?: boolean
  /** 仅探针/适配器类节点可用，且要求原样透传 */
  acceptsAny?: boolean
  optional?: boolean
  /** 运行期填充，声明期为空 */
  identity?: string
  lineage?: string[]
}
```

### 4.2 各 kind 承诺什么

| kind | 承诺 | 必须声明 |
|---|---|---|
| `table` | 行 = 样本，列 = 特征，无隐含轴序歧义 | `dtype`（列级）、可选 `unit`、`split` |
| `tensor` | 明确的轴序与轴语义 | `axes`、`dtype`；时序类必须含 `time` 轴 |
| `model` | 网络结构或权重，附带它期望的输入契约 | 输入的 `PortDescriptor`、权重 `identity` |
| `metrics` | 指标名 → 数值，**并声明在哪个 split 上算的** | `split` |
| `scaler` | 拟合参数 + **拟合所依据的 split 与行数** | `split`（必须 `train`）、列集合、方法 |
| `figure` | 图表配置 + 其引用的数据身份 | 引用列表、导出格式 |
| `any` | **不承诺任何东西** | 必须同时给出 `acceptsAny: true` |

### 4.2.1 数据源与按需拆列（规范性）

`data.source` 始终只声明一个固定输出端口：`__table__ : table`。未选择数据集时，端口仍然存在；
求值则由执行面报告数据集未绑定。端口形状不随数据列数、启用状态或时间列变化。

整表包含时间列（若有，排在最前）及数据面板中启用的数值列（按启用顺序）。时间列是整表中的
普通具名列，不再作为第二个 `__time__` 端口输出；特征列也不各自生成数据源端口。
需要某几列时，从整表连接 `data.columns`（「拆列」）并按需选择；自定义函数也可以直接接整表，
由函数代码自行取列。这样“数据源给什么”只有一份定义，具体取哪些列由下游显式表达。

`data.columns` 的“只拆这几列”参数现在接受以逗号、分号或换行分隔的**从 1 开始的特征索引**，
索引只在上游表的数值特征中计数，登记的时间列不占索引（`1` 表示第一个数值特征）。索引顺序
就是输出端口顺序；输出端口的 id 仍使用对应的真实列名。参数留空时保持原语义：按上游表的全部
列拆分。越界或非正整数索引必须在执行时报告，不得静默换成另一列。

旧工程中的数据源特征列/时间轴直连，在读入时改写为“数据源整表 → 拆列 → 原下游”的兼容链，
保留原列语义和下游连线；旧 `__time__` 端口仅作为拆列节点的兼容选择标识，由执行面按整表中登记的
时间列取值。不得在当前 `data.source` 端口清单中继续暴露这些旧端口。

### 4.2.2 绘图节点与 figure（规范性）

所有用于绘制数据图的节点都必须从图中的上游输入取得数据；不得再由绘图节点自行选择一个数据集，
也不得在断开上游后悄悄退回另一份数据。`viz.chart` 的必需输入为 `data : table`；
`viz.density` 的必需输入为 `data : table`（若只画某一列，应先用 `data.columns` 拆出该列）；
`custom.chart` 的绘图函数签名必须有一个无默认值的数据形参，并以 `{"figure": matplotlib.figure.Figure}`
返回要画的结果；函数本身决定坐标、标注、图例、配色、布局等全部画面。除代码签名里用户自定义的
普通参数外，节点不再提供图表类型或 X/Y 等绘图设置。带标量默认值的可选参数在右侧栏显示对应控件；节点卡片默认收起未接线的可选参数端口，右侧栏可临时展开接线口，这不改变端口契约。
形如 `Literal["选项一", "选项二"]` 且默认值属于选项之一的字符串参数显示为下拉选择，选项由代码静态声明，
不会根据上游表的列动态推断。自定义绘图函数中名为 `feature`、`feature_name`、`column` 或
`column_name` 的字符串参数，在其表格输入已解析出列名时显示为上游列名下拉选择；可用列名来自实际
上游输出摘要，不从数据集全量或代码文本猜测。当前选择仍保存在普通节点参数中并以字符串传给函数；
静态 `Literal` 选项优先。上游列名暂不可得时保留普通文本控件。Python 引擎将 Figure 导出为 PNG 图片，作为
figure 输出摘要的一部分传回界面；界面只显示图片，不重新解释或重画它。浏览器端 Pyodide 与本地宿主
都必须提供匹配版本的 Matplotlib。

兼容既有工程：旧绘图函数若仍返回 `DataFrame`，暂时继续按表格处理并走旧的 SVG 图表渲染路径；新建
函数的示例与规范均使用 Matplotlib Figure。`viz.chart` 与 `viz.density` 不变，仍由共享 SVG 渲染器
直接绘制上游数据。

figure 是绘图节点从已接入数据实际计算得到的产物。节点一旦有 figure 输出，就使用同一条 figure
渲染路径在节点框内直接显示；无需为了看图单独点“运行”。运行只负责把当前图登记到资产库，不能改变
节点内显示图的来源。若上游或绘图函数尚未产出数据，节点应提示等待或展示该步骤的真实错误，不得
另取导入数据集作为替代。内部训练节点的训练历史曲线是训练产物的专用视图，不属于通用绘图输入契约。

### 4.2.3 桌面固定数据集预载（规范性）

桌面本地模式可以配置一份固定 CSV，在应用启动时自动加入当前会话的数据集列表。宿主只提供该固定文件的
专用读取接口，不得接受任意文件路径；界面必须复用现有 CSV Worker 解析并生成普通数据集，不能为固定数据
另建解析或执行路径。预载只提供数据，不得静默改写已有工作流的节点或连线；新建数据源节点可以按当前
默认规则选中最近导入的这份数据。文件不存在或读取失败时，应用应显示明确状态并允许其他功能继续使用。

固定文件路径由 `SCIVIZ_FIXED_DATASET_PATH` 配置；未设置时不预载，专用端点明确返回未配置。该路径不是工程文件中的
可移植数据引用，工程仍按普通 `DatasetRef` 身份规则处理，跨机器打开时不得假设对方存在同一路径。

### 4.3 兼容规则（规范性）

**R1（any 的使用）** 内置算子原则上禁止 `any`。`any` 仅允许出现在探针、外部适配器等**原样透传**节点上，且必须在清单中登记、加载工程时汇总为 warning。理由：`any` 让类型检查退化为没有检查，一处 `any` 就能让整条链路的静态保护失效。

**R2（张量兼容）** 判据为：`rank 相同` ∧ `逐轴语义相同` ∧ `dtype 可安全提升`。尺寸允许不同，但**只允许样本轴不同**（样本数由数据决定，不是接口的一部分）。`float32 → float64` 允许，反向需显式 cast。

> 例：`(sample, channel, time)` 接 `(sample, time, channel)` 必须报 `E_AXIS_ROLE_MISMATCH`，即使形状数值恰好相等。训练里最贵的 bug 就是这类"数值对得上、语义反了"。

> **2026-09-13 补记（`metrics` 那一行）**：`eval.score` 已经产出真指标（分类 / 回归），
> 但**还没有声明"在哪个 split 上算的"** —— 那要靠 `PortDescriptor.split` 跟着数据流走。
> 现在能保证的只是"喂进去的那张表是什么就是什么"：把训练集喂进去照样能算，分数会好看，
> 而系统不会拦。这是已知缺口，与 R4 的泄漏检查一起等 PortDescriptor 落地。

> **2026-09-15 补记（`scaler` 那一行）**：标准化不再由内置 `feature.scale-fit` / `feature.scale-apply`
> 节点负责，而是由用户函数显式实现。函数可以接收 `train`、`val`、`test`，只在 `train` 上拟合
> `StandardScaler` 等标准化器，再把同一个 scaler 应用到三份数据，并直接返回
> `{"train": train_scaled, "val": val_scaled, "test": test_scaled, "scaler": scaler}`。
> `scaler` 输出保留真实 Python 对象供后续自定义函数使用，前端只显示其拟合参数摘要。

> **2026-09-16 补记（`model` / `DataLoader`）**：`train.mlp`、`train.cnn1d` 与 `train.custom`
> 的 `model` 输出是宿主会话内的真实模型句柄，数值训练结果统一从 `metrics` 端口输出；
> `history` 是逐轮表，`curve` 是可直接绘制的长表。`custom.model` 的推荐接口是直接定义
> `class Model(nn.Module)`，只描述网络结构；`MODEL_PARAMS` 中的标量与一维列表声明自动成为模型块内的
> 可编辑控件；模型的端口契约另由 `MODEL_INTERFACE` 显式声明，前端不执行用户代码，只读取安全的 Python
> 字面量并把它转换为输入/输出端口。接口端口支持现有 `any` / `table` / `tensor` / `model` / `metrics` /
> `figure` / `scaler` 类型，并可声明 `optional`、`multiple`、`shape`、`axes`、`dtype`、`unit` 和说明文字。
> `model` 输出仍是宿主会话内的模型句柄；接口输入的已连接值随定义句柄保留，供自定义训练/预测钩子通过
> `model_factory.interface` 与 `model_factory.interface_inputs` 读取。列表参数标准落地后 `custom.model` 语义版本为 0.5.0。
>
> `train.custom` 负责 Dataset / DataLoader。输入模式为「表格」时，每行是一个样本；输入模式为
> 「时序窗口」时，训练节点按 `window` / `horizon` / `stride` 在**每个已划分的数据集内部**生成
> `(sample, time, feature)`，目标取窗口之后第 `horizon` 个时间点，绝不跨 train / val / test
> 拼窗口。预测节点沿用训练时记录的同一组参数并把预测行对齐到目标行。旧式
> `build_model(spec, params)` 以及 `make_spec`、`build_dataloader`、step hooks、`fit_model`、
> `make_dataset`、`make_dataloader`、`loss_fn`、`decode_predictions` 继续兼容，但不是普通模型
> 的必需接口。Dataset / DataLoader 属于宿主运行时，不作为画布端口传递；留出集通过
> `model.predict` 生成带真实列与预测列的表，再交给 `eval.score`。

### 模型列表参数

`custom.model` 的 `MODEL_PARAMS` 可声明可编辑的一维同质列表，示例：

```python
MODEL_PARAMS = {
    "channels": {
        "type": "list[int]",
        "default": [32, 64, 128],
        "label": "通道数",
        "minItems": 1,
        "maxItems": 12,
        "itemMin": 1,
        "itemMax": 512,
    },
}
```

每个列表声明都必须显式给出 `type`：`list[int]`、`list[float]`、`list[str]` 或 `list[bool]`；列表必须是一维，元素类型统一，
不允许嵌套列表、字典、空值或混合类型；`list[int]` 每项须处于 JavaScript 安全整数范围，以保证 JSON 往返不丢精度。数值列表可用 `itemMin` / `itemMax` 限制单项；`minItems` /
`maxItems` 限制列表长度，默认分别为 0 和 64，`maxItems` 不得超过 64。即使默认值为空也须显式声明类型。
每个元素在模型节点中显示为独立控件，支持按序新增、修改和删除；列表顺序具有语义，保存时不得排序。

列表参数在 `.sciviz` / YAML 的 `node.params` 中使用规范 JSON 字符串保存（例如 `"[32,64,128]"`），
因此不改变现有工作流参数的标量 IR 契约。前端编辑器负责序列化，静态校验负责检查 JSON 形状、元素类型、
数量和范围；宿主执行前按声明重新校验并恢复成新的 Python `list`，传给 `Model.__init__`。控件默认值、
工程中保存值和宿主接收值必须遵循同一声明，不得静默截断、排序或转换非法元素。

### 4.3.1 自定义模型接口声明

`MODEL_INTERFACE` 必须是可静态解析的字典，`inputs` 与 `outputs` 可以使用列表（推荐）或以端口 id 为键的
字典简写。每个端口至少声明 `id` 与 `type`；字符串简写等价于 `{"type": "tensor"}`。端口 id 在同一方向内
必须唯一，不能覆盖保留的 `model` 输出；最多各 64 个端口。示例：

```python
MODEL_INTERFACE = {
    "inputs": [
        {"id": "features", "label": "特征", "type": "tensor", "shape": ["batch", "feature"], "dtype": "float32"},
        {"id": "mask", "label": "掩码", "type": "tensor", "optional": True},
        {"id": "context", "type": "table", "multiple": True},
    ],
    "outputs": [
        {"id": "prediction", "label": "预测", "type": "tensor", "shape": ["batch", "target"]},
        {"id": "embedding", "type": "tensor", "optional": True},
    ],
}
```

`optional` 默认为 `False`，`multiple: true` 遵循 R13 的有序多入语义；`shape` 只描述轴（整数或字符串），不把
样本数写死，`axes` 与 `shape` 长度不一致时静态校验报错。声明非法类型、重复 id、超过 64 个端口、动态表达式或
未闭合字面量都必须在 L1 阶段拒绝，不能等宿主执行才猜测。未声明 `MODEL_INTERFACE` 时保持兼容：只有固定的
`model : model` 输出，训练节点继续按原有 `input_shape` / `output_shape` 注入模型结构。

### 4.4 复合组块（规范性）

**R15（组块是内联子图）**

1. 组块节点在 `WorkflowNode.group` 中携带完整子 `Workflow`，以及输入绑定、输出绑定、参数绑定；定义不得只存于 `localStorage` 或本机模块清单。组节点 `params` 只保存对外参数的当前值。
2. 每个输入绑定持久化稳定的外部端口 `id`、端口描述符及一个或多个内部目标（节点 ID + 端口 ID）；输出绑定持久化稳定的外部端口 `id`、描述符及内部来源。导入后不得根据位置或当前端口顺序猜映射。
3. 参数绑定以稳定外部 key 指向一个内部节点参数，并保存 `ParamSpec`。执行展开时以组实例的外部参数值覆盖绑定的内部参数；未暴露的内部参数保留子图自身值。组参数和边界端口都可同时被外部连线驱动，连线优先于参数字面值，沿用普通节点规则。对外参数值与它所指的内部节点参数值是**同一个值的两个视图**，任何编辑入口（组面板、子图内的节点面板、由代码签名推导出参数的同步）都必须同时更新这两处，不得只改其中一份；读工程文件时若两处不一致，按**对外值**对齐内部副本（对外值才是执行时生效的那一份），不得用内部副本改写对外值。
4. 组边界端口的类型与内部目标/来源一致。静态校验必须检查映射引用存在、内部端口存在、外部边兼容，且展开后的图无环；无效映射以 `E_GROUP_INVALID` 报告。嵌套组可递归，但定义不得循环，且须受实现的最大深度限制。
5. 执行前以组实例 ID 为前缀命名内部节点 ID，并将边界连线翻译成内部连线，再交给同一计划器与执行器。GUI、CLI 的校验、计划和运行必须使用同一展开规则。任何会改变展开图的组定义、绑定或外部参数变化都必须改变对应节点及下游指纹。
6. 组块创建保留所选节点间全部内部边；边界外的每条入边、出边都必须映射到外部端口。端口 ID 在创建时生成并随文件保存；重命名或移动内部节点不得改变外部端口 ID。

**R3（单位）** 必须同量纲；跨量纲一律拒绝。同量纲不同单位（`Hz` ↔ `kHz`、`g` ↔ `mm/s²`）必须由**显式单位换算算子**完成，不允许隐式猜测。

**R4（拆分泄漏，静态可判）** 任何 `fits: true` 的输入端口若其 `split ≠ train`，报 `E_SPLIT_LEAK`。这是防数据泄漏的第一道闸：标准化器、特征选择、超参搜索的拟合统计量只能来自训练集。

## 10. 训练函数与兼容节点（2026-09-17）

`train.function` 是新的通用 PyTorch 训练算子，执行面为本地宿主。它的固定语义端口为：
`model: model`、`train: table`、可选 `val: table`、可选 `scaler: scaler`；`metrics`、
`history`、`curve` 为稳定输出。训练代码参数从 `fit_model` 的签名解析：宿主保留参数
（`model_factory`、`train_data`、`test_data`、`scaler`、`device`、`params`、`env`）不成为端口；
其余标量默认值成为可编辑参数端口，无默认值参数为必需参数端口。UI 使用轻量签名解析，
静态校验与执行端都必须按同一解析结果处理参数。

训练函数负责从原始训练/测试表创建 Dataset 与 DataLoader，并负责算法循环、验证和早停；宿主只负责
按函数给出的形状实例化模型、设备放置、取消与进度通道、指标类型检查、标准输出包装、模型句柄和产物归档。
返回的指标值必须是有限/可转换的数值；训练实现应定期调用 `env.check_cancel()` 和
`env.progress(...)`。用户代码和数据共同进入指纹，训练节点声明 `stochastic`，不得缓存。

`train.function` 不声明也不解释「标签列」「特征列」「工作段」「窗口」或 DataLoader 参数；这些规则
只存在于用户的 `fit_model` 代码及其签名中。宿主将 `train` / `val` 端口值原样注入为
`train_data` / `test_data`。旧签名 `fit_model(model, train_loader, val_loader, ...)` 只为已有工程兼容，
仍走旧的默认 Dataset 适配器；新建节点不得生成该签名。

画布客户端把 `train.function` 视为显式启动节点：未收到本次会话的启动请求时状态为 `manual`，不进入
求值队列；收到请求后按普通指纹与 Job 规则执行。训练完成、失败或取消后，该次请求即消费完毕。输入指纹
变化而没有新请求时必须清除旧模型输出并回到 `manual`，不能自动重训，也不能把旧模型交给下游。
取消使用既有宿主 `cancel(nodeId)` 通道；取消是 `cancelled`，不是 `error`。

`train.mlp`、`train.cnn1d` 与旧固定参数协议的 `train.custom` 继续注册以读取和运行旧工程，
但生命周期标为 `legacy`：新建节点库隐藏，CLI catalog 仍列出并标明生命周期。不得静默把旧节点
改写为 `train.function`，因为两者训练语义与参数来源不同。

**R5（随机性）** 随机算子必须声明 `seed` 参数；`determinism = seeded` 而参数中无 `seed` 时报 `E_UNSEEDED_STOCHASTIC`。

**R6（不可复现项）** `determinism = stochastic` 的产物禁止进缓存，且必须在运行清单中列为"不可复现贡献项"，使复现性报告诚实地承认它。

> **2026-09-13：`determinism` 已落地。** 每个算子在 `NodeTypeDef` 里声明三级中的一档（必填）；
> 运行清单的每个节点带 `operator.determinism`，并把 `stochastic` 且**真的产出过东西**的节点
> 列进 `unreproducible`（附一句人话的原因）。两处口径值得记住：**用户代码（`custom.*`
> 与自建模块）一律报 `stochastic`** —— 里面有没有随机源只有代码自己知道，我们替它承诺不了；
> **训练报 `stochastic` 而不是 `seeded`** —— GPU 上有非确定性归约，本机实测 CPU / GPU 结果
> 不逐位相同，给了 seed 也不足以承诺复现。宁可报得悲观。
>
> 仍未做：指纹里还没有 `determinismClass`（R5.1 列了它），所以改一档确定性不会让已有产物失效；
> 缓存本身也还没实现（R5.3 / R6.4）。

**R7（算子版本）** 每个算子必须声明 `version`（语义化版本）与 `implementationHash`。**二者任一变化都必须使指纹失效**。

> **2026-09-13：`implementationHash` 已落地。** `nodeFingerprint` 现在带上
> `impl=<算子实现哈希>`。哈希由 `scripts/gen-operator-hashes.mjs` 从算子源码生成——
> 函数体 + 该文件的模块上下文（imports 与模块级常量）一起进哈希，所以改常量会让
> 同一文件里的算子一起失效（宁可多失效，不可少失效）；只增删 `OPERATORS` 表不影响
> 已有算子。生成物进版本库，`operatorHashes.test.ts` 守着它不会静默过期。
> 哈希同时出现在 `sciviz catalog` 的 `implementationHash` 字段里，供 agent 比对两次
> 运行的差异。
>
> **2026-09-13：`version` 也落地了。** 每个算子在 `NodeTypeDef` 里声明语义化版本（必填），
> 当前一律 `0.1.0` —— 版本化从这一天开始，此前没有任何算子有版本可比。
> 与哈希的分工写在该字段的注释里：**哈希回答"实现变了没有"（机器算的），版本回答
> "换过行为口径没有"（人写的）**。
>
> **仍未做：R11 的版本迁移闸门。** 工程文件里还没有记录"这份图当时用的是哪一版算子"，
> 所以 `E_OPERATOR_VERSION_CHANGED` 依旧列在 `notChecked` 里：没有"旧版本"可比，
> 就判不出"变了没有"。

**R8（血缘）** 每个产物必须记录产出它的 `(runId, nodeId, portId)` 及其全部上游身份。血缘用于回答"这个数字从哪一步来"，也是图表可追溯的前提。

**R9（数值范围不属于契约）** 端口只承诺形状语义、单位与血缘，不承诺数值范围。数值假设（如"峭度应 > 3"）用 §7 的抽样校验表达，违反仅告警、不阻断。

**R10（序列化）** 图必须能序列化为纯文本并往返无损。

> 现状差异：现有 YAML 导出只含 `name / description / nodes(type,label,params,position) / edges(source,sourcePort,target,targetPort)`，没有算子版本、数据身份、环境、图整体指纹。据此无法复现，只能重建结构。

**R11（版本迁移）** 打开记录了旧算子版本的工程时，必须显式选择"按新版本迁移"或"锁定旧版本"，**禁止静默继续**。这是 ComfyUI 式失效（节点包升级导致老工作流静默变形）的结构性解法。

**R12（画布批注不属于本规格）** 表格、思维图和图片这类**画布批注**不在端口类型系统里：它们没有端口、不流动值、不进 `catalog`、不参与求值，因此也不进指纹、不进运行清单。它们与图同处一个工程文件的顶层 `annotations:` 段，但每条批注必须明确属于一个画布层级：`groupPath` 是从根工作流到所属子工作流的组块节点 ID 数组；空数组表示主画布，缺少该字段的旧文件也按空数组读取。视图只显示其 `groupPath` 与当前导航路径完全相同的批注，不能把主画布或其他组块中的批注带入当前层。

批注位置按所属画布层级解释。创建或粘贴到组块内部的批注归该组块所有；组合工作流节点时，可以将同次选中的批注一并纳入新组块；单独选中一个组块及批注时，可以将所选批注移入该组块。封装、解散、复制或删除组块时，必须同步更新、复制或移除对应 `groupPath` 下的批注，不能留下不可见的孤儿批注。此层级归属不改变批注不是算子的边界。

**R12.1（记录不放在画布上）** "人记下来的文字"（实验笔记）不在画布批注里，也不在计算图里：它住在工程文件顶层 `notebook:` 段的一份 **Markdown 正文**里，与图一样不参与求值、不进指纹、不进运行清单。三条判据：

1. **记录是一维的，画布是二维的。** 便签曾经是画布上的第四种批注，结果是"便签一多，画布就被文字占满"：缩小看不清内容、放大看不全结构。记录回到列表面（可搜索、可折叠、可复制），画布只放结构与少数大件。
2. **`kind: 'note'` 不再是合法批注。** 打开旧工程时这些条目会被忽略，**并且必须报数**（"有 N 条便签被忽略，记录已改到「实验笔记」栏"）—— 丢的是人写的字，不能静默。
3. **笔记可以引用节点**（`@[名字](node:节点id)`）：点引用，画布聚焦到那个块。节点被删时显示为灰色，不报错 —— 笔记是历史记录，不该因为图改了就读不出来。内嵌图片按最长边压到 1600 再进文件（工程文件要能 diff、要能带走）。

**R12.2（项目报告）** 报告是工程顶层 `reports:` 中的独立 Markdown 文档集合，不是计算节点，也不是一份会话的临时回答。每篇报告至少有稳定 `id`、标题、Markdown 正文、创建和修改时间；由 Agent 任务生成的报告还记录所属 `sessionId`、`taskId` 与已成功工具结果的证据引用。同一任务续写同一篇报告，不得在重试时制造重复条目。旧工程没有 `reports:` 时读为空集合，工程格式仍为 v1。

会话 JSONL 中的 `task_checkpoint.finish.report` 是当时提交的**审计快照**，允许保留原文供追溯；当前可编辑、可下载的交付物以工程 `reports:` 为准。两处含义必须在界面上区分，用户后来编辑项目报告时不得把旧会话快照显示成当前版本。

报告随 `.sciviz` 一起保存、打开和本地展示。图像由**当前已完成的绘图节点结果**在本机捕获，核对当前输入指纹与 ready 状态后再嵌入报告 Markdown；不得把旧图冒充新图。嵌入图像使用有大小上限的 `data:image/png` URL，使单独带走工程文件时仍能看到图；来源块、画布层级和图像摘要应可追溯。报告、图片与实验笔记均不进入计算图、求值指纹或运行清单；报告中的数字仍须引用实际运行或检查结果，报告正文不能改写 `run.json` 的机器事实。工作流以后变化时，已有报告保留为历史记录，不静默改写其中的图像或结论。

报告管理的资源上限为每工程 100 篇、每篇图片外的正文 1 MiB、每任务暂存图片 20 张、单张嵌入图不超过 8 MiB、单篇合计图片不超过 24 MiB、全工程序列化报告不超过 64 MiB。越界必须明确拒绝，不能裁掉正文或图片后当作保存成功。未保存草稿可在本机暂存以供恢复，但 `.sciviz` 是带走工程时的权威副本；已打开工程文件时写回失败不得当作成功，尚无文件句柄时须明确标出本地草稿待保存。保存失败时 Agent 任务不得标记最终报告已完成。

**R13（多入端口）** 一个输入端口默认**只接一条线**（第二根撞 `E_PORT_OCCUPIED`）。唯一的例外是算子显式声明 `multiple: true` 的端口：它接受任意多条入边，算子按**连线在图里的先后顺序**拿到一个有序列表。

> 为什么需要这一类，而不是"想接多路就加个参数说几个槽位"：`data.collect`（列拼表）原先正是
> 那么做的 —— 一个「列数」参数配 `col_1…col_N` 个端口。代价很具体：这个节点在画布上占一整张
> 卡片，而"接第 N+1 路"要么先去框上改数字、要么靠界面偷偷替用户改图（自动加槽）。
> 拼表的语义本来就是"把手上所有能拼的都拼进来"，**槽位数是一个用户不该做的决定**。
>
> 三条边界，都是会静默出错的那种：
> 1. **顺序是内容的一部分。** 同一个拼表节点，先接 A 还是先接 B，产出的列序不同 ——
>    所以顺序取"连线在 `edges` 里的先后"，不是字典序、也不是完成先后。它进指纹，换序会重算。
> 2. **仍然只有一个端口。** 连线判据、画布上的连接点、清单里报的端口都只有一个；
>    展开成引擎侧的 `col_1…col_N` 是**求值计划**在边界上做的一次翻译，不是第二处端口真相。
> 3. **`E_PORT_OCCUPIED` 对它不适用。** 其余端口照旧：占用不自动替换，
>    因为替换会静默丢掉别人接的那根线。

## 5. 求值键（指纹）

**R5.1** 指纹是"这次求值对应什么输入与实现"的完整判据：

```
fingerprint(node) =
    operatorId @ operatorVersion
  + implementationHash
  + normalize(params)
  + 输入端口到上游 identity 的映射
  + 数据身份 DatasetRef（内容哈希 + 启用列 + 时间列 + 采样率）
  + determinismClass
```

**R5.2** 指纹不取哈希、直接比较字符串。理由：几十个节点、每条几百字节，比对比哈希更便宜；而哈希碰撞会静默漏掉一次重算，那是最难查的一类错。（沿用现有选择，见 `src/engine/plan.ts` 注释。）

**R5.3** 指纹即**缓存键**：`指纹 → 产物`。同一指纹再次出现时可直接复用产物而不重算——这正是"可复现"在工程上的落地形式。

**R5.4（位置不是内容）** 指纹里的"上游 identity"取**节点 id**，不取运行时 id（带组路径的那个）。把块封装进组块、解散组块、再嵌一层都只改变它在画布上的位置，不改变任何一个像素的计算，因此**不得改变任何节点的指纹**；运行时 id 仍用于输出、运行时状态与运行清单的归属，只是不进指纹。

同理，`normalize(params)` 必须把"键缺失"与"键等于该参数的声明默认值"当成**同一个状态**：签名参数没写进 `params` 时，求值用同一份声明默认值兜底（`buildInputBindings`），所以把默认值补写进去只是同一个值换个地方存 —— 而 `params` 整份进指纹，补写会让指纹变。据此，组块对外参数物化到内部节点、以及读工程时的镜像对齐，判据都是"这次写入会不会改变内部节点的**有效值**"。

这条的理由是训练制品：`.sciviz` 的 `modelArtifacts` 引用与宿主 `meta.json` 都按指纹**严格比对**，位置一动指纹就变的话，"训练一次、之后把块整理成组块"当场失效，而用户看不出为什么。

**R5.5（制品匹配按身份）** 判断"工程里的引用是不是属于这个节点这次的计算"时，先把两边指纹归一，再比字符串。归一抹掉三样**记账**：

1. **位置**：`port:group:[…]:` 里的组路径（R5.4 的同一句话在比较处的落地）；
2. **会话内计数**：`#数字` 形式的"这次会话里算过几次"。它跨会话不可比 —— 每次开工程都从 1 重新数，拿它比对等于要求"训练那天上游刚好也只算过一遍"，于是"动一下上游再训练、下次打开"就认不出自己的权重；
3. **算子实现哈希**：`impl=` 后面那 64 位十六进制（本节点的、以及上游链路里嵌着的都抹）。

三样是同一条纪律：**记账不是内容**。实现哈希进指纹是给**缓存**用的（R5.3：改一次实现，图里已算出的结果不能再当成最新的），以及给运行清单留"这份产物出自哪一版实现"的痕迹；它不是"这是哪个实验"的一部分 —— 同一份用户参数、同一段用户代码、同一份数据、同一条上游链路，实验身份不因为**我们自己**换了一版算子实现而改变。

**为什么必须把它从制品身份里拿掉（2026-09-22 实测）。** 宿主侧实现一改，`impl=` 就变，于是工程里所有训练节点的引用当场全部"不匹配"。调度器按设计**不自动恢复**，节点回到 `manual`（"当前训练设置与已保存制品不匹配，旧结果已过期并保留"），下游评估 / 图表块跟着停摆 —— 用户看到的是"权重读不到"，而他自己的配置、代码与数据一个字节都没动。当天那一例：`gpu_ops.py` 改过之后 `train.function` 与 `custom.model` 的哈希从 `4945d798…` / `be5c486a…` 变成 `4f20827a…` / `8983eee5…`，同一份工程里三个训练块的引用全部失效，而两边指纹**只有这两处 `impl=` 不同**。

**安全性不靠这条比对，靠宿主逐项实测。** 恢复时宿主独立校验 ① `meta.json` 的文件校验值 ② 制品身份与版本 ③ 训练节点**当前参数**（含用户代码）与制品记录的一致性 ④ 模型定义源码哈希与模型参数 ⑤ **train / val / test 三份输入的实际内容哈希**（`dataIdentity`，逐行重算）。这几项任一不符就显式失败（"…的数据与当前工程不一致；请重新定位制品或重新训练"），不会静默用错权重。换言之：归一只回答"这份权重属于哪个实验"，兼不兼容由**实测**回答。

**残余（写在明处）。** 如果一次算子改动改变了**训练语义**（例如早停口径）而没有改变数据、参数与模型代码，旧权重仍会被自动沿用。它记在制品清单的 `modelImplementation` 里，但界面不做"这一版实现已过期"的判断 —— 这条比"我们自己修一次算子，用户所有训好的权重全部作废"代价小；真需要按实现重训时，用户显式点「重新训练」即可。

恢复请求发给宿主时带的是**引用里记的那一份指纹**（也就是制品 `meta.json` 里的值），宿主据此严格比对制品身份与完整性，不引入第二套模糊规则。

> 抹掉会话计数意味着：**上游是 `stochastic` 的节点重跑之后，训练节点的内容指纹不变**，制品匹配认不出这一次与上一次的差别。这条残余是刻意的：内容指纹本来就是 stochastic 的全部判据（§5 的现状说明），而"别复用随机节点的产物"由算子自己声明（`determinism` 不进缓存）来守，不靠制品匹配。真正的防护是**不缓存**，那一条没变。

> **现状（2026-09-13，T18 落地时对齐过一遍）**。指纹今天由这几项拼成（`src/engine/plan.ts`）：
> 算子类型 + **算子实现哈希** + 参数（排序后）+ 每个输入端口的上游 **identity**
> （上游节点的**指纹** + 上游输出版本号）+ 数据源那一端多带的三项（**数据集内容哈希**、
> 启用列、时间列）。
> 实现哈希**留在指纹里**（它管缓存与复现），只是**不进制品匹配的身份**（R5.5）——
> 两处判据要的是两件事，混在一起就会"我们自己修一次算子，用户训好的权重全部作废"。
>
> 两处与 R5.1 的差：① `operatorVersion` 没有单独进指纹（实现哈希变了就变了，版本号是给人看的）；
> ② `determinismClass` 也没进 —— 它通常随实现一起变。**这两条记在 §9 的差异清单里，不假装已经齐了。**
>
> 而"输入端口到上游 identity 的映射"这一项，在 T18 之前**没有真的做**：那时只记上游的**版本号**，
> 而版本号每次都从 1 重新数 —— 于是"结构相同、上游喂的却是另一份数据"的两张图，下游指纹一模一样。
> 加缓存时当场撞上：两个实验的"时域特征"被判成同一份缓存，第二个实验直接拿到第一个实验的数。
> 现在上游指纹（内容）与版本号两条都记：内容让指纹**跨会话**可认，版本号让同一次会话里
> "上游重算过"这件事仍然会让下游失效（`stochastic` 的节点重算两次得到不同的数，而它的指纹不变）。

## 6. 求值与运行

**R6.1（统一 Job）** 每一次"算出某节点某端口"都是一次 Job，具有：指纹、执行等级、状态生命周期、日志、产物、确定性等级。实时小算子与小时级训练**共用同一套 Job 语义**，只是执行等级不同。

| 执行等级 | 目标延迟 | 触发 | 要求 |
|---|---|---|---|
| `interactive` | < 100 ms | 自动、防抖 | 可抢占、可丢弃 |
| `background` | 秒 ~ 分钟 | 自动排队 | 有进度、可取消 |
| `batch` | 分钟 ~ 小时 | 显式触发或排队 | 可取消、可恢复、产物落盘 |

> **2026-09-13：`execClass` 已落地。** 每个算子在 `NodeTypeDef` 里声明一档（必填）：
> 现存的实时算子全部 `interactive`，训练与超参搜索是 `background`，`eval.explain`
> （t-SNE / UMAP / Grad-CAM）也是 `background` —— 大数据上要几十秒，且不是每次改参数
> 都该重算。运行清单的每个节点带 `operator.execClass`。
> **仍未做**：等级目前只是**声明 + 记录**，调度还没有按它分流（一条路径全按 interactive 跑），
> 进度与取消也没有（待办 T7）。`batch` 这一档尚无算子使用。

> **2026-09-13：进度与取消落地了（T7），但只在宿主这一侧。**
> 宿主按 Job 报 `nodeProgress`（节流 ~4/s），`cancel` 是一面旗子、由算子在可中断点上读
> （`runtime.Env.check_cancel`）；取消之后节点停在 `cancelled`、产物丢掉、**指纹照记**
> ——这样调度不会立刻把它重跑一遍。浏览器那侧做不到：Pyodide 里一次求值是同步调用，
> 中断插不进去，所以 `cancelNode` 在那里返回 false，界面也不显示取消按钮。
> 仍欠：调度**还没有**按 `execClass` 分流（长任务仍占着同一条求值通道，只是现在能报进度、能停了）。

**R6.2（模拟是一种适配器能力，不是一条平行代码路径）** 尚未实现真算法的算子，由"模拟适配器"提供 Job 结果，并在产物与运行清单中标记 `simulated: true`。

> 现状差异：两条路径仍并行（`src/engine/*` 真算、`src/workflow/executor.ts` 模拟），但**分界不再是第二处清单** —— 2026-09-13 起每个算子在 `NodeTypeDef` 里用必填的 `execClass`（`engine` / `simulated`）自己声明，`ENGINE_NODES` 白名单已删除，漏改一处不再可能。仍欠两项：模拟产物尚未在运行清单里带 `simulated: true`；无头侧不产出任何模拟数值。

**R6.3** 运行记录 `RunManifest` 是复现的最小单位，至少包含：图指纹、算子版本集合、数据身份集合、参数全集、随机种子全集、环境信息、每个产物的身份与 `simulated` 标记、不可复现贡献项清单。

> **2026-09-13 状态**：图指纹、算子版本集合（`operatorVersions`）、数据身份集合（`datasets[].contentHash`）、
> 环境信息（`environment`：Python / numpy / pandas / scipy / torch / CUDA / 显卡与显存）、
> 不可复现贡献项（`unreproducible`）**已在清单里**。
> **产物的身份**也有了一半：训练落盘的文件进 `nodes[].artifacts`，每条带类别、路径、字节数与
> **产出它的输入指纹**（路径是宿主机器上的绝对路径，指纹才是能跨机器比较的那一项）。
> 仍缺三项：**参数全集与随机种子全集**没有单独列出（它们在每个节点的指纹里，但指纹不是给人读的）、
> **R8 的血缘**没写全（产物还答不出"它是哪几个上游身份算出来的"）、
> `simulated` 目前只落在节点上（`nodes[].simulated`），没有落在产物上。

**R6.4** 缓存规则：`deterministic` 与 `seeded`（种子一致时）可缓存；`volatile` 与 `stochastic` 不可缓存。

**R14（训练模型制品）**

1. 每次成功训练必须分配唯一 `artifact_id`。训练配置指纹用于识别设置，不得作为可覆盖的制品路径。制品在 `.artifacts/<artifact_id>/` 下不可变保存，至少包含模型 `state_dict`、校验摘要和恢复元数据。
2. 恢复元数据必须记录模型定义版本/代码引用、构造参数、输入输出规格、特征与目标顺序、标准化状态、训练函数与参数、训练集及用于验证/早停的数据身份、指标、训练历史和环境信息。制品必须在登记前完成临时写入与校验，最终目录通过原子改名发布。
3. `.sciviz` 的 `modelArtifacts` 是工程级引用，与 `graph.nodes[].params` 分离；`nodes[].artifacts` 继续记录本次运行产物。制品本体不嵌入 YAML，引用不参与节点指纹。
4. 自动恢复只允许使用工程内已有的引用，且当前训练节点指纹必须与引用保存的训练指纹完全相同。**打开 `.sciviz` 工程就是自动恢复的触发时机**：工程加载完成后，宿主必须按节点引用验证并恢复模型，使下游节点继续求值；用户不需要另点“加载权重”。修改训练实现/模型定义及参数、训练或早停数据、上游预处理均使引用成为非当前结果；只改训练节点下游不使引用过期。过期引用仍保留并可回退；训练节点应提供显式重新训练动作，创建新制品前不得自动重训或覆盖旧制品。恢复失败时不得静默训练或降级到其他制品，必须说明制品缺失、损坏或不兼容，并提示重新定位制品或重新训练。
5. 跨工程选择制品必须由用户明确发起，并检查输入特征顺序、形状和标准化方式等推理契约；不得因结构相似而自动复用。
6. 内存模型只可作为当前宿主进程的加速状态。关闭、重开和恢复均以磁盘制品与工程引用为准。自动清理不得删除任何工程、固定或收藏引用；引用来源无法完整确认时不得推断无人使用。只有无引用且超过保留期限的制品才可列为候选，展示候选和引用情况并经用户确认后，方可移入可恢复回收区。

## 7. 三级校验

| 级别 | 时机 | 判据 | 违反后果 |
|---|---|---|---|
| **L1 静态** | 连线时 / 加载工程时 | 类型、轴序、单位、`split`、缺 seed、必需输入、算子版本 | **阻断该动作**（拖线被拒、`connect` op 被拒、加载时给错误码）；**不否决补丁写入**，见下 |
| **L2 抽样** | 首次求值后 | 实际形状 / dtype / 单位与声明是否一致 | 告警 + 记入清单 |
| **L3 运行清单** | 每次 Run 结束 | 与上一次同类 Run 对比，检测漂移 | 记录 + 可查询 |

**"阻断"到底阻断什么（2026-09-22 明确）。** L1 是判据的级别，不是写入的闸门。一份工程
长期处在"搭到一半"的状态是常态 —— 人会把半截实验留在画布上，也会把许多子实验收进
一个子空间省地方，那些地方本来就断着；手改过文件、旧编辑器写过的工程也可能带着
两处不一致。所以写入（补丁）只被**能归因到某条 op 本身**的拒绝拦住：

1. op 引用了这一层里不存在的东西（节点 / 连线 / 数据集 / 子空间路径）；
2. op 要连的端口不存在、类型不兼容、已被占用、会成环；
3. op 带的参数不是声明过的键，或值不合 `ParamSpec`；
4. op 要落的子空间定义**形状**残缺（缺 `workflow` / `inputs` / `outputs` / `parameters`）。

其余整图 L1 的问题（含 `E_MISSING_INPUT` 与 `E_GROUP_INVALID` 的深层映射检查）一律
**照跑、照报**，进 `PatchResult.validation` 交给调用方，由人决定要不要接着改。
反过来说，`validate` 通过仍然意味着"这张图现在可以跑"，只是**不通过不再意味着不许改**。
这条规则的反面教训记在[接口文档](./接口文档.md) §2.8 与[开发日志](./开发日志.md)：
把整图 L1 当闸门时，工程里任何一处历史遗留问题都会让 agent 一个块都改不动，
而拒绝理由是空的 —— 调用方只能谎报一个别的错误码，于是模型开始无限重试。

> 现状：L1 已实现并三边共用（`src/contract/validate.ts`）—— 连线判据只有一处
> （`checkConnection`：界面拖拽、补丁的 `connect`、校验器判已有的边都走它）。
> L3 走运行清单（`RunManifest`）；**L2（首次求值后的抽样核对）还没做**。校验器把它
> 查不了的规则明写在 `notChecked` 里，而不是默默当成通过；还差哪些见 §9。

## 8. 错误码表

稳定、机器可读、可被 agent 与 CI 直接消费。

| 码 | 触发条件 | 级别 | 建议动作 |
|---|---|---|---|
| `E_TYPE_MISMATCH` | 端口 `kind` 不兼容 | L1 | 换端口或插入适配算子 |
| `E_RANK_MISMATCH` | 张量轴数不同 | L1 | 检查是否需要 reshape 算子 |
| `E_AXIS_ROLE_MISMATCH` | 轴语义不同（如 `(s,c,t)` 接 `(s,t,c)`） | L1 | 插入转置并确认语义 |
| `E_DTYPE_DOWNCAST` | 需要降低精度 | L1 | 显式 cast |
| `E_UNIT_MISMATCH` | 量纲不同 | L1 | 插入单位换算算子 |
| `E_SPLIT_LEAK` | 拟合类输入非 `train` | L1 | 把拟合移到训练分支 |
| `E_UNSEEDED_STOCHASTIC` | 随机算子缺 `seed` | L1 | 补种子 |
| `E_MISSING_INPUT` | 必需输入未接线 | L1 | 接线 |
| `E_OPERATOR_VERSION_CHANGED` | 工程记录的算子版本 ≠ 当前 | L1 | 显式迁移或锁定旧版本 |
| `E_SHAPE_DRIFT` | 实际形状与声明不符 | L2 | 检查上游或更新声明 |
| `E_DTYPE_DRIFT` / `E_UNIT_DRIFT` | 实际 dtype / 单位与声明不符 | L2 | 同上 |
| `E_EXECUTION_FAILED` | 运行期异常（含 traceback） | L3 | 查看 traceback |

**G0 补入的码。** 上表管的是"契约违约"，而下表管的是"文件与图本身就有毛病"——两者都需要稳定码，否则校验器只能吐散文，agent 与 CI 无从消费。前缀表示严重度：`E_` 阻断，`W_` 告警。

| 码 | 触发条件 | 级别 | 建议动作 |
|---|---|---|---|
| `E_YAML_INVALID` | 文件不是合法 YAML，或缺少 `nodes` 等必需结构 | L1 | 修 YAML 语法或补齐必需字段 |
| `E_UNKNOWN_OPERATOR` | 节点类型不在算子清单里（拼写错误、自建模块缺失） | L1 | 用 `catalog` 查可用算子；自建模块需先在界面里导入 |
| `E_DUPLICATE_NODE_ID` | 两个节点用了同一个 id | L1 | 给其中一个换 id，连线跟着改 |
| `E_DANGLING_EDGE` | 连线引用了不存在的节点 | L1 | 删掉这条连线，或把节点补回来 |
| `E_UNKNOWN_PORT` | 连线引用了该节点上不存在的端口 | L1 | 按 `catalog` 里的端口清单重接 |
| `E_CYCLE` | 图里有环，求值顺序不存在 | L1 | 断开环上的一条连线 |
| `E_PARAM_INVALID` | 参数不是声明过的键、类型不符、或超出 `min`/`max` 与选项范围 | L1 | 按 `catalog` 里的参数 spec 改值 |
| `W_DATASET_UNRESOLVED` | 动态端口的上下文暂不可得（如函数签名未完成、拆列节点尚未得到上游列名或特征索引映射） | L1 | 补全函数签名或先运行上游以取得列/特征视图；CLI `--columns` 仅声明数据集列视图。**此时不判连线错误**——"算不出来"不等于"线接错了" |
| `W_IMPORT` | 导入时的非阻断提示（数据集重新绑定、暂时接不上的连线等） | L1 | 读提示内容，不影响继续校验 |

**G2 补入的码。** 补丁动作要把"这条 op 自己落不下去"与"图还没接完"分开：前者必须拦住，
后者是正常的中间状态（人可能正搭到一半）。自 2026-09-22 起，**判据只看前者** ——
`E_UNKNOWN_REF` / `E_PORT_OCCUPIED` / `E_PARAM_INVALID` / `E_TYPE_MISMATCH` /
`E_UNKNOWN_PORT` / `E_CYCLE` 这些能逐条归因到某条 op 的才拒绝整批；`E_GROUP_INVALID`
与其余整图问题只报告（见 §7 的说明）。**在 op 级检查里 `E_GROUP_INVALID` 仍然算拒绝**：
封装 / 解散本身算不出来时，这条 op 确实没地方落。

| 码 | 触发条件 | 级别 | 建议动作 |
|---|---|---|---|
| `E_UNKNOWN_REF` | 补丁里的 id 在本工程里不存在（节点 / 连线 / 数据集） | L1 | 用正确的 id；或先用 `addNode` / `addDataset` 建出来 |
| `E_PORT_OCCUPIED` | 要连的输入端口已经被别的连线占用（声明 `multiple: true` 的多入端口除外，见 R13） | L1 | 先 `disconnect` 那条旧连线，再 `connect`。**不自动替换** —— 替换会静默丢掉别人接的线 |
| `E_GROUP_INVALID` | 组块的端口/参数绑定指向不存在的内部节点或端口，或边界声明与内部契约不兼容 | L1 | 双击组块检查内部连线与边界映射；必要时重新封装 |
| `E_PATCH_BASE_MISMATCH` | 机器生成的图补丁基线与当前 `editFingerprint` 不同，或未提供基线 | L1 | 重新读取当前工程、重新 plan 与 dry-run，不要套用旧 op |

## 9. 从现状到本规格的差异清单（P0 工作项）

按"是否正在产生错误结果"排序，前四项是缺陷而非优化：

1. **指纹缺算子版本** → 改算子后旧结果仍显示为最新。
2. **数据集身份是形状签名而非内容哈希** → 换了数据但列名列数相同时不被察觉。
3. **`fs` 是算子参数而非数据属性** → 同一数据可被两条链路用不同采样率解释。
4. **无 `split` 血缘规则** → "先分帧再划分"造成的窗口跨集泄漏无法被拦住。
5. `PortType` 是粗枚举（`any|table|tensor|model|metrics|figure|scaler`）→ 升级为 `PortDescriptor`（§4.1）。
6. `portsCompatible` 只做 `any`/同值判断 → 升级为完整的 L1 规则集（§4.3）。
7. `data.preview` 的输入端口用了 `any` → 按 R1 登记为透传节点。
8. YAML 无版本、无环境、无数据身份（R10）。
