## 1. 新训练入口：代码定义训练函数

节点库只提供一个新的 PyTorch 训练入口：`train.function`（「自定义训练」）。用户像写
`custom.script` 一样编辑 Python 函数；函数签名是参数声明的唯一来源：

- 函数名必须是 `fit_model`。
- 宿主上下文参数 `model_factory`、`train_data`、`test_data`、`scaler`、`device`、`params`、`env`
  由宿主注入，不生成连线或控件。数据端口名与这些保留名同样不能声明成自定义参数。
- 其余带标量字面量默认值的参数自动变成节点内可编辑控件及可接线参数端口；不带默认值的
  参数是必需参数端口；复杂 Python 默认表达式保留由 Python 函数本身处理，不伪装成空字符串控件。
- 端口由轻量签名解析器推导，不执行用户代码。解析器支持的签名与默认值范围以
  `src/workflow/functionSignature.ts` 为准；它不是完整 Python AST。

训练函数直接接收训练表和测试表。滑动窗口、按工作段分组、Dataset / DataLoader、列选择、优化器、
损失、训练循环和早停都属于用户函数；宿主不得先把表改写成默认 Dataset。`model_factory(...)` 只在
用户函数已经确定输入/输出形状后实例化已连接的模型定义。函数应返回：

```python
{"model": model, "metrics": {"训练损失": 0.1}, "history": [{"轮次": 1, "训练损失": 0.1}]}
```

`model` 可省略（默认使用传入模型），`metrics` 的值必须是数值，`history` 可为 DataFrame、
记录列表或空值。统一的 `model` / `metrics` / `history` / `curve` 输出、模型句柄、产物归档和
下游 `model.predict` 仍由宿主负责；训练函数必须在循环中调用 `env.check_cancel()`，并通过
`env.progress(ratio, message)` 报告进度。

## 2. 宿主负责的边界

`train.function` 保留模型定义和数据的语义端口：`model`、`train`、可选 `val`（界面显示为
「测试集（早停/验证）」）、可选 `scaler`。`custom.model` 默认只描述 PyTorch 网络结构；如需把模型
接入非标准数据或多路上下文，在代码中增加 `MODEL_INTERFACE`，由同一份声明生成显式输入/输出端口。
宿主只提供模型工厂、设备、取消/进度和产物包装。表格/时序窗口布局、标签/特征列、工作段边界、batch 大小、
随机种子及早停口径都必须写在 `fit_model` 内，由函数签名中有默认值的参数生成控件。

`model_factory` 的调用形式为
`model_factory(input_shape, output_shape, task="regression", feature_names=(), target_names=(), metadata=None)`；
它返回已经放到 `device` 上的 `torch.nn.Module`。同一次执行只能建立一份模型。若函数没有调用工厂，
且返回值里也没有可识别的模型，宿主必须报错，不得猜输入维度。

动态训练函数的用户参数写在 `fit_model` 签名中，不再给新节点堆叠优化器、调度器、精度、梯度累积、
早停等固定字段。需要这些能力时，用户在自己的函数里实现。宿主不声称代管用户循环里的具体数值，
但仍统一提供取消、进度、错误呈现、输出校验、训练产物与模型传递。

训练执行只走本地宿主，因为 PyTorch 不在浏览器 Pyodide 的共享包表中。浏览器端负责编辑、解析签名、
校验数据流和发起执行，不在浏览器中加载 torch。

画布中的 `train.function` 是显式启动的后台任务：接好模型与数据后保持「待开始」，只有用户点击节点卡片
上的「开始训练」才提交。训练期间同一位置显示「停止训练」，并通过宿主的协作式取消在下一个
`env.check_cancel()` 检查点结束。输入、代码或参数变化会让旧模型失效并回到「待开始」，不得自动用新输入
偷偷重训。CLI 的 `run` 本身就是一次显式启动，因此无头执行不需要额外按钮状态。

## 3. 稳定输出与下游语义

| 输出端口 | 契约 |
|---|---|
| `model` | 宿主会话内的真实 PyTorch 模型句柄，供 `model.predict` 使用 |
| `metrics` | 用户返回的数值指标，并由宿主补充设备、参数量、用时和产物信息 |
| `history` | 用户返回的逐轮记录表；列由函数返回内容决定 |
| `curve` | 从 `history` 生成的统一绘图长表；缺少可绘制轮次或指标时允许为空 |

模型参数仍由 `custom.model` 的 `MODEL_PARAMS` / 构造函数签名解析。构造函数推断继续只负责标量默认值；
数组结构由 `MODEL_PARAMS` 显式声明。标量类型沿用现有控件；列表使用 `type: "list[int]"`、
`"list[float]"`、`"list[str]"` 或 `"list[bool]"`，并以 `default: [...]` 给出同质的一维默认值。
可选 `minItems` / `maxItems` 限制项数（缺省 0 / 64，硬上限 64），可选 `itemMin` / `itemMax` 限制
数值项。列表必须显式声明 `type`。`custom.model`（语义版本 0.5.0）将列表显示为逐项编辑控件，保留元素顺序并支持新增/删除；工程参数用规范 JSON
字符串保存，宿主校验后恢复为新的 Python 列表再调用 `Model`；整数项限于 JavaScript 安全整数范围。嵌套列表、混合类型、空值和超限列表拒绝，
不做静默修正。数据集身份和训练函数代码都进入节点指纹；训练节点是随机过程，不进入结果缓存。

### 3.1 自定义模型的显式接口

`MODEL_INTERFACE` 是接口的唯一声明源，不要求用户再维护一份注册表。它是 Python 字面量字典，包含
`inputs` / `outputs` 两组端口；端口可写成列表或 `{id: descriptor}` 简写，descriptor 支持 `type`、`label`、
`optional`、`multiple`、`shape`、`axes`、`dtype`、`unit` 与 `description`。端口类型沿用数据契约的七种类型，
因此表、张量、模型、指标、图和标准化器可以混接，但仍按类型兼容规则校验。前端和宿主都只读取字面量，
不执行模型代码来“猜端口”。接口输入的运行时值保存在模型定义句柄中；自定义训练/预测钩子可从
`model_factory.interface`（规范化端口描述）和 `model_factory.interface_inputs`（已连接值）读取。
没有声明时保持旧协议，只有 `model : model` 输出。

## 4. 旧工程兼容

`train.mlp`、`train.cnn1d` 与旧版固定参数协议 `train.custom` 标记为 `legacy`：

- 从新建节点库隐藏；目录里已有的旧工程仍能解析、校验、打开和运行。
- 注册表继续保留这些节点定义和宿主算子，不改旧 type、不静默迁移、不丢旧参数。
- CLI catalog 仍列出它们，并用 `lifecycle: "legacy"` 标明只用于兼容；agent 创建新图应使用
  `train.function`。
- 新旧节点的参数与执行版本互不覆盖。旧工程原有固定控制项只对旧节点生效。

## 5. 验收判据

- 新建节点库仅暴露通用的「自定义训练」，不暴露 MLP/CNN/旧固定自定义训练节点。
- `fit_model` 的标量默认参数能自动生成控件与参数端口；编辑代码后新增参数出现、删除参数不残留；
  保留参数的用户值不丢失。
- `custom.model` 的四类列表参数都能逐项编辑、保存/重载并由宿主以 Python 列表收到；非法元素类型、数量或
  数值范围在前端静态校验和宿主边界校验中均明确拒绝。
- 自定义训练可从模型定义、训练表和可选测试表完成一次真实宿主训练；测试表可由用户函数作为
  早停验证集，并产出四个稳定输出；
- 训练节点未点击开始时不占用 GPU；开始后按钮立即可停止，取消状态不记为失败；参数或上游变化后
  不自动重训，旧产物不得继续冒充当前输入的结果。
  `model.predict` 可消费新训练节点的模型句柄。
- 训练函数漏接必需动态参数、签名错误、返回非数值指标时给出明确错误，不静默忽略。
- 旧 `train.mlp` / `train.cnn1d` / `train.custom` 工程仍加载并运行，且它们在 catalog 中标成 legacy。
